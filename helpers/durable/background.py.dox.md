# Detached Background Work

`background.py` owns encrypted, source-pinned requests for plain utility/checker inference, frozen memory recall, automatic memorization, and history compression. `TaskHandle` is an inert checkpoint reference, never a serialized coroutine. A claimed producer atomically publishes its request manifest and all one-use resource grants before starting a detached process. Credentials pass only in that process's environment; provider-configured credentials can restart unsent outboxes on another host. Explicit wrapper-only credentials need that configured worker.

The broker holds a pinned PostgreSQL role. Each inference has an immutable prepared-input receipt and a one-use send intent followed by an encrypted known result. Worker death does not cancel a broker. Broker death after a send intent holds unknown inference; neither observers nor the bounded shared scanner resend it. Pause/Stop/generation/restore-epoch controls fence new sends. Unknown utility/function hooks, model options, unsupported messages, or source drift hold before inference. The exact bundled utility secret mask is projected before the request is encrypted; detached inference does not rediscover global hooks without its original agent.

Recall freezes typed documents and float32 vectors, with bounded exact inner-product search and the existing area/threshold limits. Automatic memory uses `memorization.py`: frozen revision, summary/consolidation/embedding receipts, deterministic document IDs, and one atomic shared-memory patch/operation receipt. Concurrent fragment/solution outboxes may reuse their known patch at a newer revision only when the embedding identity and every typed record/vector in their own frozen area are unchanged. New, edited or deleted affected-area records produce a known conflict; unrelated areas remain intact. A lost commit acknowledgement resolves the exact operation receipt and never repeats inference or the mutation. The PostgreSQL outbox survives an enqueue-to-spawn crash and may finish after the originating successful turn.

`history.py` first performs the ordinary deterministic large-message truncation on the claimed loop, including oversized newest messages, and clears provider continuation when their summaries change. If history remains over limit, it summarizes a frozen old prefix into a bulk while retaining the two newest current messages and original records for inspection/provider cleanup. It does not mutate live history in the background. Before the next prompt, a known projection replaces only a matching prefix, preserves appended input, and clears provider continuation. A changed prefix is discarded; a new request uses the new input. Generic pending asyncio/Deferred tasks still require an explicit adapter.
